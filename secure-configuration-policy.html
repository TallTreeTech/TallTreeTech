Secure Configuration Policy

Document Owner: IT Director

Effective Date: November 14, 2025

Review Date: November 14, 2026

Version: 1.0

1. Purpose and Scope

1.1 Purpose

This policy establishes secure configuration standards for all IT systems and devices used by the Company. It ensures that systems are hardened against attack by removing unnecessary functionality, implementing security controls, and following industry best practices. Secure configuration is a fundamental requirement of the UK Cyber Essentials scheme.

1.2 Scope

This policy applies to:

  • All servers (physical, virtual, and cloud-based)
  • All desktop computers and laptops (Company-owned and BYOD)
  • All mobile devices accessing Company data
  • All network devices (routers, switches, firewalls, wireless access points)
  • All operating systems (Windows, macOS, Linux, mobile OS)
  • All applications and software
  • Cloud services and platforms
  • Development, test, and production environments

1.3 Policy Statement

All IT systems and devices shall be configured securely to minimize vulnerabilities and reduce the attack surface. Default configurations must be hardened, unnecessary services disabled, and security settings enabled. Configuration standards shall be documented, implemented consistently, and verified regularly.

2. Secure Configuration Principles

2.1 Core Principles

Minimize Attack Surface

Remove or disable all unnecessary software, services, features, and functionality. Only components required for business purposes should be enabled.

Least Functionality

Systems shall be configured to provide only the functionality required for their intended purpose. Additional capabilities must be disabled or removed.

Secure by Default

Default security settings shall be strengthened. Default passwords must be changed, and secure settings enabled from initial deployment.

Defense in Depth

Multiple layers of security controls shall be implemented. No single control should be relied upon exclusively.

Consistent Standards

Configuration standards shall be documented and applied consistently across similar systems. Deviations must be documented and approved.

3. General Configuration Requirements

3.1 Default Settings

All systems must have default settings hardened before deployment:

  • Default passwords: Must be changed immediately (never use in production)
  • Default accounts: Unnecessary default accounts must be disabled or removed
  • Default services: Unnecessary default services must be disabled
  • Sample content: Default sample files, applications, and content must be removed
  • Error messages: Detailed error messages revealing system information must be disabled

3.2 Unnecessary Software and Services

To reduce attack surface:

  • Remove software and applications not required for business purposes
  • Disable services that are not needed
  • Remove or disable development tools from production systems
  • Disable remote management services unless specifically required
  • Remove legacy protocols and services (e.g., SMBv1, Telnet, FTP)

3.3 Auto-Run Features

Auto-run and auto-play features must be disabled to prevent malware execution:

  • AutoRun for removable drives disabled on all Windows systems
  • AutoPlay disabled for all media types
  • Automatic execution of macros in documents disabled by default
  • Scripts from untrusted sources blocked

3.4 System Hardening

All systems shall be hardened according to recognized standards:

  • CIS Benchmarks: Apply relevant CIS (Center for Internet Security) benchmarks
  • Vendor guidelines: Follow security hardening guides from vendors (Microsoft, Apple, etc.)
  • NCSC guidance: Apply NCSC end user device security guidance
  • Industry best practices: Implement additional hardening appropriate to threat environment

4. Operating System Configuration

4.1 Windows Systems

4.1.1 Security Features

  • Windows Defender/Anti-Malware: Enabled with real-time protection
  • Windows Firewall: Enabled for all network profiles
  • BitLocker: Enabled on all laptops and portable devices
  • User Account Control (UAC): Enabled at appropriate level
  • Windows Update: Automatic updates enabled or managed centrally
  • Secure Boot: Enabled where supported
  • Credential Guard: Enabled on Windows 10/11 Enterprise (where available)

4.1.2 Disabled Features

  • SMBv1 protocol disabled
  • PowerShell v2 removed
  • Guest account disabled
  • LAN Manager authentication disabled
  • Remote Registry service disabled
  • Unnecessary scheduled tasks removed

4.1.3 Registry and Policy Settings

  • Group Policy settings applied consistently
  • Screen lock timeout enforced (15 minutes maximum)
  • Password complexity and length requirements enforced
  • Remote Desktop limited to authorized users only (with NLA enabled)
  • Windows Script Host configured securely

4.2 macOS Systems

4.2.1 Security Features

  • FileVault: Enabled for full disk encryption
  • Firewall: Enabled and configured appropriately
  • Gatekeeper: Enabled (App Store and identified developers only)
  • System Integrity Protection (SIP): Enabled
  • Automatic Updates: Enabled for security updates
  • Screen lock: Enabled with password required

4.2.2 Privacy and Security Settings

  • Location Services configured appropriately
  • Analytics and diagnostics data minimized
  • Automatic login disabled
  • Password required on wake from sleep/screensaver
  • Guest account disabled

4.3 Linux Systems

4.3.1 Security Features

  • SELinux or AppArmor: Enabled in enforcing mode
  • Firewall (iptables/firewalld): Configured with default deny
  • Disk encryption (LUKS): Enabled on laptops and sensitive servers
  • Automatic updates: Enabled for security patches
  • SSH: Key-based authentication, root login disabled

4.3.2 Service Hardening

  • Unnecessary services disabled (xinetd, telnet, rsh, etc.)
  • Secure versions of services used (SSH instead of Telnet)
  • Service accounts locked (no interactive login)
  • Kernel parameters hardened (sysctl settings)
  • File permissions restricted appropriately

4.4 Mobile Devices (iOS and Android)

4.4.1 Required Settings

  • Screen lock: PIN/password/biometric required (6+ digits)
  • Encryption: Device encryption enabled
  • Auto-lock timeout: Maximum 5 minutes
  • OS updates: Kept up to date
  • App sources: Only official app stores (no sideloading)
  • Find My Device: Enabled for remote wipe capability
  • Bluetooth: Disabled when not in use

4.4.2 Mobile Device Management (MDM)

Corporate mobile devices must be enrolled in MDM with:

  • Security policy enforcement
  • App management and distribution
  • Remote wipe capability
  • Device compliance monitoring
  • Encryption verification

5. Application Configuration

5.1 Application Whitelisting

Where technically feasible:

  • Implement application whitelisting to allow only approved applications
  • On Windows: Use AppLocker or Windows Defender Application Control
  • Block execution from temporary locations and user-writable directories
  • Regularly review and update whitelist

5.2 Web Browser Configuration

5.2.1 Approved Browsers

Approved browsers (kept up to date):

  • Microsoft Edge (Chromium)
  • Google Chrome
  • Mozilla Firefox
  • Safari (on macOS/iOS only)

5.2.2 Browser Security Settings

  • Automatic updates: Enabled
  • Pop-up blocker: Enabled
  • Phishing/malware protection: Enabled (Safe Browsing, SmartScreen)
  • Password manager: Company-approved password manager only
  • Extensions: Limited to approved and necessary extensions
  • Cookies: Third-party cookies blocked or limited
  • Do Not Track: Enabled
  • HTTPS enforcement: HTTPS-only mode where available

5.2.3 Restricted Browser Features

  • Disable Java plugin (if still present)
  • Adobe Flash blocked or removed
  • ActiveX controls restricted to approved sites only
  • Automatic downloads prevented or restricted

5.3 Microsoft Office Configuration

  • Macros: Disabled by default, prompt for signed macros only
  • Protected View: Enabled for files from internet and unsafe locations
  • Automatic updates: Enabled
  • DDE: Disabled (Dynamic Data Exchange)
  • External content: Blocked or prompt before loading
  • File blocking: Block execution of dangerous file types

5.4 Email Client Configuration

  • HTML rendering restricted or sanitized
  • Automatic download of images disabled (prompt user)
  • Links and attachments from external sources flagged
  • Dangerous attachment types blocked (.exe, .scr, .vbs, etc.)
  • Encryption available and encouraged (S/MIME, PGP)
  • Junk/spam filtering enabled

5.5 PDF Reader Configuration

  • JavaScript in PDFs disabled
  • Protected mode/sandbox enabled
  • Automatic updates enabled
  • Opening non-PDF attachments from PDFs blocked

6. Network Device Configuration

6.1 Firewall Configuration

6.1.1 Firewall Rules

  • Default deny: Block all traffic by default, allow only explicitly approved traffic
  • Inbound rules: Limit inbound connections from internet to minimum required
  • Outbound rules: Control outbound traffic to prevent data exfiltration
  • Rule documentation: Each rule documented with business justification
  • Rule review: Firewall rules reviewed quarterly

6.1.2 Firewall Management

  • Management interface access restricted to authorized administrators
  • Strong authentication required (MFA preferred)
  • Management access only from trusted networks (not directly from internet)
  • All configuration changes logged
  • Configuration backups taken before changes

6.2 Router and Switch Configuration

  • Default passwords changed immediately
  • Unnecessary services disabled (HTTP, Telnet, SNMP v1/v2)
  • Secure management protocols used (SSH, HTTPS)
  • Network segmentation implemented
  • VLAN configuration documented
  • MAC address filtering where appropriate
  • Port security enabled

6.3 Wireless Network Configuration

6.3.1 Corporate Wi-Fi

  • Encryption: WPA3 or WPA2-Enterprise (no WPA or WEP)
  • Authentication: 802.1X with RADIUS for corporate network
  • SSID: Non-revealing name (don't identify company)
  • SSID broadcast: Enabled (hiding provides false security)
  • Isolation: Client isolation enabled where appropriate
  • Password: Strong pre-shared key (if using WPA2-PSK)

6.3.2 Guest Wi-Fi

  • Separate SSID and VLAN from corporate network
  • No access to internal corporate resources
  • Captive portal for terms acceptance
  • Time-limited access or rotating password
  • Web filtering and content restrictions

6.4 VPN Configuration

  • Strong encryption protocols (IKEv2, OpenVPN, WireGuard)
  • No weak encryption (PPTP prohibited)
  • Certificate-based authentication preferred
  • Multi-factor authentication required
  • Split tunneling disabled (all traffic through VPN)
  • Kill switch enabled to prevent data leaks

7. Server Configuration

7.1 General Server Requirements

  • Server role-specific builds (dedicated purpose per server)
  • Minimal software installation (only required packages)
  • Unnecessary user accounts removed
  • Service accounts properly configured (no interactive login)
  • Logging enabled and centralized
  • Time synchronization configured (NTP)

7.2 Web Server Configuration

  • TLS/SSL: TLS 1.2 minimum, TLS 1.3 preferred
  • Certificates: Valid certificates from trusted CA
  • HTTP headers: Security headers configured (HSTS, CSP, X-Frame-Options)
  • Directory listing: Disabled
  • Error pages: Custom error pages (no system information)
  • Server banner: Minimal information disclosure
  • Unnecessary modules: Disabled or removed

7.3 Database Server Configuration

  • Sample databases and accounts removed
  • Strong authentication required
  • Least privilege for database accounts
  • Network access restricted (firewall rules)
  • Encryption for data at rest and in transit
  • Audit logging enabled for administrative actions
  • Regular backups with tested restore procedures

7.4 File Server Configuration

  • Share permissions and NTFS/file permissions both configured
  • Default administrative shares removed or secured
  • Anonymous access disabled
  • Audit logging enabled for sensitive data
  • Quotas configured to prevent resource exhaustion

8. Encryption Requirements

8.1 Data at Rest Encryption

Full disk encryption required for:

  • All laptops and portable computers
  • All mobile devices
  • Removable media (USB drives, external hard drives)
  • Servers containing sensitive data

Encryption methods:

  • Windows: BitLocker
  • macOS: FileVault 2
  • Linux: LUKS (dm-crypt)
  • Mobile: Built-in device encryption

8.2 Data in Transit Encryption

Encryption required for:

  • Web traffic: HTTPS (TLS 1.2 minimum)
  • Email: TLS for SMTP, encrypted connections for IMAP/POP
  • File transfers: SFTP, FTPS, or SCP (not plain FTP)
  • Remote access: VPN with strong encryption
  • Database connections: TLS/SSL enabled
  • API communications: HTTPS only

8.3 Encryption Key Management

  • Encryption keys stored securely (not with encrypted data)
  • Key recovery mechanisms documented and tested
  • Keys rotated according to schedule
  • Access to keys restricted to authorized personnel

9. Configuration Baselines and Standards

9.1 Baseline Documentation

Configuration baselines shall be documented for:

  • Windows 10/11 workstations
  • macOS workstations
  • Windows Server editions
  • Linux servers (by distribution)
  • Mobile devices (iOS and Android)
  • Network devices (firewalls, routers, switches)
  • Cloud service configurations

9.2 Baseline Contents

Each baseline document shall include:

  • Purpose and scope
  • Security settings and rationale
  • Services and features to enable/disable
  • Software to install/remove
  • Network settings
  • Authentication and access control settings
  • Logging and monitoring configuration
  • Verification procedures

9.3 Configuration Templates

  • System images and templates created based on baselines
  • Templates include all security hardening
  • Templates updated quarterly and when baselines change
  • New systems deployed from approved templates

10. Configuration Management

10.1 Configuration Change Control

Configuration changes must follow change management process:

  • Configuration changes requested and approved
  • Impact on security assessed
  • Changes documented and tracked
  • Rollback procedures prepared
  • Changes tested before production deployment

10.2 Configuration Monitoring

  • Automated tools monitor configuration compliance
  • Configuration drift detected and reported
  • Non-compliant systems flagged for remediation
  • Regular configuration audits conducted

10.3 Configuration Backup

  • Configuration backed up before changes
  • Configuration documentation maintained
  • Backup configurations tested for restoration
  • Network device configurations backed up automatically

11. Cloud Service Configuration

11.1 Cloud Security Configuration

Cloud services must be configured securely:

  • Multi-factor authentication enabled for all accounts
  • Least privilege access implemented
  • Strong password policies enforced
  • Audit logging enabled
  • Data encryption enabled (at rest and in transit)
  • Public access disabled unless explicitly required
  • Security monitoring and alerts configured

11.2 Cloud Service Baselines

Configuration baselines maintained for:

  • Microsoft 365 tenant settings
  • Azure subscriptions and resources
  • AWS accounts and services
  • Google Workspace
  • Other SaaS applications

12. Compliance and Verification

12.1 Configuration Audits

Audit Type Frequency Scope
Automated Compliance Scanning Weekly All managed devices
Manual Configuration Review Quarterly Critical servers and network devices
Comprehensive Security Audit Annually All in-scope systems
New System Verification Before deployment Each new system

12.2 Non-Compliance Remediation

When non-compliant configurations are identified:

  • Non-compliance documented with details
  • Risk assessed (likelihood and impact)
  • Remediation plan created with timeline
  • High-risk issues remediated within 7 days
  • Medium-risk issues remediated within 30 days
  • Low-risk issues remediated within 90 days
  • Progress tracked until resolution

12.3 Exceptions and Waivers

Deviations from secure configuration standards:

  • Must be documented with business justification
  • Require IT Director approval
  • Must include compensating controls
  • Subject to regular review (at least annually)
  • May affect Cyber Essentials certification

13. Roles and Responsibilities

13.1 IT Director

  • Overall responsibility for secure configuration policy
  • Approve configuration baselines and standards
  • Approve exceptions and waivers
  • Review configuration audit results
  • Ensure resources for compliance

13.2 System Administrators

  • Implement secure configurations on systems
  • Maintain configuration baselines
  • Monitor configuration compliance
  • Remediate non-compliant configurations
  • Document configuration changes

13.3 All Users

  • Do not modify security settings without authorization
  • Report configuration issues or concerns
  • Comply with application usage restrictions
  • Do not install unauthorized software

14. Policy Review and Maintenance

This policy shall be reviewed:

  • Annually as a minimum
  • When new system types are introduced
  • When security incidents reveal configuration weaknesses
  • When Cyber Essentials requirements are updated
  • When vendor security guidance changes significantly
